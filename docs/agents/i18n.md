# i18n

Read when you add or change UI text, a locale, or anything direction-dependent.

| Where                                  | Holds                                                                                                           |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `packages/i18n/src/messages/<locale>/` | One JSON file per namespace: `common`, `auth`, `dashboard`, `account`, `badges`, `tables`, `marketing`, `email` |
| `packages/i18n/src/config.ts`          | `locales`, `defaultLocale`, `directions`, `localeCookieName`, `resolveLocaleFromHeaders`                        |
| `packages/i18n/src/format.ts`          | `formatDate`, `formatNumber`, `formatRelativeTime`                                                              |
| `apps/web/src/i18n/request.ts`         | next-intl request config: locale from the cookie, messages from `loadMessages`                                  |
| `apps/web/src/i18n/locale-actions.ts`  | `setLocale` Server Action                                                                                       |
| `apps/web/src/components/locale/`      | `LocaleSwitcher` (language menu), `HtmlLocaleSync`                                                              |

## Text

- **Every user-facing string** comes from the messages, read with `useTranslations` in Client Components and `getTranslations` in Server Components and Server Actions. This includes `aria-label`s, toasts and errors.
- **Add a key to every locale together** (`en` and `fa` here). Messages are typed from `en` (`apps/web/src/types/i18n.d.ts`), so `t("missing.key")` fails `typecheck`. `packages/i18n/src/load-messages.test.ts` fails when another locale lacks a key or a `{placeholder}`.
- **Placeholders** use `{name}`, passed as `t("key", { name })`.
- **`email` is server-only.** The root layout strips it from the client payload. Mail code reads it through `@repo/email`.
- **Cached functions** return message keys, not translated text, unless the locale is part of their arguments.
- **URLs stay English** (`*-routes.ts`). Only labels are translated.
- **Auth API errors** come from `@better-auth/i18n` in the same locale, so they need no keys in `messages/`.

## Locale and direction

- **The cookie decides.** The locale is the `NEXT_LOCALE` cookie: no `[locale]` segment, no middleware, no URL prefix.
- **Crawlers get `en`.** They send no cookie, so they index the default locale, and there are no `hreflang` alternates.
- **`lang` and `dir` are set only on `<html>`, in the root layout.**
  - An inline script applies them from the cookie before the first paint, so there is no flash of the wrong direction.
  - `HtmlLocaleSync` keeps them in step after a switch, and `DirectionProvider` passes the direction to Base UI.
- **Styles use logical properties** (`ms-*`, `me-*`, `ps-*`, `start-*`, `text-start`), so they work in both directions — [ui.md](./ui.md).
- **Dates and numbers** go through `formatDate`, `formatNumber` and `formatRelativeTime` with the current locale (`getLocale()` or `useLocale()`).

## Add a locale

1. Copy `messages/en/` to `messages/<locale>/`, translate it, and add the imports in `packages/i18n/src/load-messages.ts`.
2. Add the locale and its direction to `locales` and `directions` in `packages/i18n/src/config.ts`.
3. Add its label and flag to `localeOptions` in `apps/web/src/components/locale/locale-switcher.tsx`.
4. Check that `@better-auth/i18n` ships the locale (`packages/auth/src/auth.ts` maps `locales` to its translations). Add an Open Graph locale in `apps/web/src/app/layout.tsx`.

`pnpm typecheck` and `pnpm test` then point at anything missed.

## Remove a locale

Remove it from `locales` and `directions` in `config.ts`. TypeScript then flags every `Record<Locale, …>` that still lists it. Delete `messages/<locale>/` and its imports. With one locale left, `LocaleSwitcher` renders nothing.
